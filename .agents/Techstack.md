CodeTrack — Technology Stack, Architecture & File Placement Guide
Companion to [Plan.md](../Plan.md) and [decision.md](../decision.md). V1 is a multi-user, online Next.js coding-preparation and revision tracker with manual question entry.

1. Fixed technology choices for V1
Responsibility	Technology	Why / where it runs
UI and routing	Next.js App Router, React, TypeScript	React pages and layouts in src/app; server-rendered pages where appropriate
Backend	Next.js Server Actions + Route Handlers on Node.js	Mutations in src/server/actions; HTTP endpoints in src/app/api
Styling	Tailwind CSS, shadcn/ui, CSS variables	src/app/globals.css, src/components/ui
Database	PostgreSQL	Hosted managed SQL service (not browser-accessible)
ORM	Prisma	prisma/schema.prisma, migrations in prisma/migrations, singleton in src/lib/db.ts
Authentication	Auth.js with Prisma adapter	src/auth.ts, src/app/api/auth/[...nextauth]/route.ts; Auth.js session checked on server
Input validation	Zod	src/lib/validations/*.ts; validate again on server even if client validates
Forms	React Hook Form + Zod resolver	Question, auth, settings forms in client components
Rich text	Tiptap	src/components/editor; store structured document JSON and sanitize rendering
Code highlighting	Tiptap CodeBlock Lowlight + lowlight	Note editor extension, not a server dependency
Analytics charts	Recharts	Client chart components in src/components/charts
Theme	next-themes	src/components/providers/theme-provider.tsx
Dates	date-fns + date-fns-tz (or Temporal-compatible utility)	src/lib/dates; business rules based on each user's timezone
Icons	lucide-react	All pages/components
Uploads	S3-compatible private object storage	Signed upload/access URLs generated by server; metadata in PostgreSQL
Unit/integration tests	Vitest + Testing Library	tests/unit, tests/integration
End-to-end tests	Playwright	tests/e2e
Hosting	Vercel + managed PostgreSQL + private bucket	Web/API on Vercel; persistent DB and image object storage separately


No separate Express API for V1. Next.js server code runs on Node.js. The browser must never receive database credentials or secret keys.

Version rule: Install current mutually compatible stable versions, pin dependencies through the lockfile, and consult each package's version-matched docs. This guide intentionally does not hard-code potentially outdated version numbers.
2. Architectural boundaries
Browser (React client components)
    |
    | form submit / navigation / HTTP request
    v
Next.js app router / server actions / route handlers
    |
    v
Authentication + authorization + Zod validation
    |
    v
Service layer (question, revision, stats, source, streak)
    |
    v
Prisma repository / SQL transaction layer
    |
    v
PostgreSQL

Rich text image upload -> authenticated upload endpoint -> signed private bucket upload
Stored note references -> authorized retrieval endpoint -> signed read URL
- Pages compose UI and fetch initial server data; do not put complex revision calculations in JSX.
- Client components handle form state, filters, dialogs and editor controls; do not import Prisma or secrets.
- Server actions handle app-internal mutations; enforce authentication, permissions, validation and ownership on each invocation.
- Route handlers handle genuine HTTP endpoints, uploads and integration-style operations. Avoid duplicating the same business logic in actions and routes.
- Services implement business rules and transactions; repositories run scoped database queries.
- Validation schemas can be shared but server-side validation is mandatory.
- Activity events are written by successful meaningful changes; viewing does not update last activity.

5. Database model ownership and relationships
Keep Prisma schemas centralized in prisma/schema.prisma (or split into Prisma schema files only if configured explicitly).
Model	Main fields / constraints
User	id, name, email UNIQUE, credentials/auth relations
UserSettings	userId UNIQUE, timezone, theme, revisionMode, revisionIntervals, dailyGoal
Category	id, name, ownerId? (global seeded vs user-owned category)
Topic	id, categoryId, parentTopicId?, ownerId?, name
Question	id, title, categoryId, topicId, difficulty, createdById
Source	id, platform, externalQuestionId?, url, displayLabel?
QuestionSource	questionId, sourceId, isPrimary
UserQuestion	id, userId, questionId, status, addedAt, solvedAt?, lastActivityAt; unique (userId, questionId)
QuestionNote	id, userQuestionId, contentJson, updatedAt
RevisionSchedule	id, userQuestionId, mode, step, nextDueDate, pausedAt?, version
RevisionHistory	id, scheduleId, revisionNumber, scheduledFor, completedAt, notes?, completionKey UNIQUE
ActivityEvent	id, userId, userQuestionId?, kind, occurredAt
Attachment	id, userId, noteId, objectKey, mimeType, byteSize
Tag, UserQuestionTag	User-owned tags and join table


V1 simplification: User-created questions are private, even though Question and UserQuestion are separated to allow future shared catalog entries. All query access starts with userId ownership. Avoid allowing public question catalog editing in V1.

Authentication models: Add any adapter-required Account, Session, and VerificationToken fields/relations according to the selected Auth.js adapter setup. For email/password, implement password hashing, reset token expiration and rate limiting; Auth.js credentials alone does not create a registration system.
6. Where a feature is implemented (step by step)
Example A — User clicks “Save Question”
1. UI: src/app/(app)/questions/new/page.tsx renders src/components/questions/question-form.tsx.
2. Form validation: src/lib/validations/question.schema.ts validates title, topic, platform ID, URLs, status, rich notes.
3. Server action: src/server/actions/question.actions.ts verifies session and validates input again.
4. Service: src/server/services/question.service.ts checks category/topic ownership and duplicates.
5. Database transaction: src/server/repositories/question.repository.ts creates Question/UserQuestion/Source joins/Note, writes ActivityEvent, and sets lastActivityAt.
6. UI refresh: Revalidate relevant route or refresh server data, then redirect to detail or clear form for “Save & Add Another.”
7. Sort: /questions queries ORDER BY lastActivityAt DESC, id DESC within the current user.
Example B — User clicks “Mark Revised”
1. UI: src/components/revisions/complete-revision-dialog.tsx collects optional notes.
2. Action: src/server/actions/revision.actions.ts validates revision ID, session and input.
3. Service: src/server/services/revision.service.ts runs an atomic transaction with a concurrency guard or unique completion key; records completed occurrence once; calculates the next date; updates schedule and user's lastActivityAt; writes ActivityEvent.
4. UI: The revision leaves due queue, revision history updates, and the question moves to top of recent activity list.
5. Tests: tests/integration/complete-revision.test.ts verifies double submit is idempotent and a different user cannot complete someone else's revision.
Example C — User opens Stats
1. Page: src/app/(app)/stats/page.tsx parses URL date/category filters.
2. Service: src/server/services/stats.service.ts computes date-range boundaries in the user's timezone, then queries aggregate data through stats.repository.ts.
3. UI: src/components/charts/*.tsx renders prepared datasets; avoid fetching all events in the browser to aggregate them there.
4. Definition: Question completion uses solvedAt/completion-event time, revisions use completedAt; pending/overdue are as-of snapshot metrics, not added to daily completed totals.

9. Development and deployment workflow
1. Initialize Next.js App Router with TypeScript, ESLint, Tailwind and src/ directory.
2. Add shadcn/ui and install PostgreSQL, Prisma, Auth.js, Zod, React Hook Form, Tiptap, Recharts, next-themes, date utilities, lucide icons.
3. Set up .env.local, database schema, migrate and seed stable categories/topics.
4. Build root theme provider and authenticated layout/sidebar; implement auth and onboarding.
5. Build question form, list sorted by lastActivityAt, detail page and source links.
6. Add Tiptap notes and private image uploads.
7. Implement revision engine and concurrency-safe completion, then revision center.
8. Implement analytics, streak and activity page.
9. Test multi-user isolation, timezone boundaries, double-submissions, mobile and keyboard accessibility.
10. Deploy to Vercel with production PostgreSQL and private storage, run migrations using a controlled deployment step, configure backups and logs.

Production: Use `prisma migrate deploy` rather than `prisma migrate dev`. Ensure one controlled migration process, reliable connection pooling for serverless, environment isolation, least-privilege DB accounts and backups.

10. V1 priorities / explicit non-goals
- **Implement**: manual entry, links and platform question IDs, rich notes, statuses, category hierarchy, recent activity sorting, manual/automatic revision and preserved history, stats, dark mode, streaks, multi-user privacy and responsive web UI.
- **Defer**: automatic platform metadata retrieval, scraping, browser extension, bulk importing, reminders, gamification/leaderboards, public sharing and offline sync.
- **Preservation rule**: Do not remove, rename, refactor or redesign existing functionality without explicit approval. Build incrementally from the agreed [Plan.md](../Plan.md), [Techstack.md](./Techstack.md), and [decision.md](../decision.md).
